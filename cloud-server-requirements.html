Feature matrix

What each feature needs

Use this as a support triage checklist. “Planned” means the Server capability is in the 2026.5 LTA scope, but its customer-facing documentation or final constraints are still being completed.

FeatureSonarQube CloudSonarQube Server, 2026.5 LTA
Vortex: Context Augmentation + Agentic Analysis
Available, Cloud
  • Cloud Team annual or Enterprise plan, plus Sonar Agent Essentials.
  • Organization entitlement enabled, and a project connected to Cloud.
  • At least one CI analysis on a long-lived branch after Agentic Analysis is enabled. A recent CI context is essential for high-precision verification.
  • Personal access token, not a project, global, or scoped-org token.
  • CLI integration or a local self-hosted MCP server. Docker or another OCI runtime is needed for the MCP path.
  • For the full Guide + Verify MCP workflow, use a self-hosted MCP server, not the Cloud-hosted endpoint.
  • Planned as part of the 2026.5 LTA Vortex scope.
  • Requires the Server agentic deployment: additional containers and customer-provided shared storage, S3-compatible object storage or a shared filesystem.
  • Use Docker Compose or Helm. ZIP deployment cannot provide the isolation model and is out of scope for agentic workloads.
  • Exact edition, entitlement, host, network, and sizing guidance remains pre-release.
Remediation Agent
Available, Cloud
  • Cloud Team annual or Enterprise, plus Sonar Agent Essentials.
  • Project bound to GitHub or Azure DevOps. Backlog flows work on both; PR remediation is GitHub-only.
  • Customer-provided LLM provider API key.
  • Enable per project. An organization admin configures automated backlog schedules.
  • Developer review is required, the agent creates suggestions and PRs but does not merge them.
  • Planned for 2026.5 LTA, with a separate subscription and Enterprise or Data Center availability indicated in current implementation work.
  • Complete all setup gates: activate add-on, deploy containers, configure LLM provider, grant DevOps platform write permissions, enable the agent/schedule.
  • Use supported deployment infrastructure and shared storage, plus controlled network egress to the LLM and required Sonar services.
  • Configure the SCM to require review of agent-created PRs, no auto-merge.
Hunter Agent
Beta, Cloud
  • Currently presented as a Beta Verify capability in AC/DC documentation.
  • Confirm organization entitlement and supported project configuration before enabling, as the published requirement detail is still evolving.
  • Findings are surfaced through the regular project issue flow.
  • Planned for 2026.5 LTA on the same Unified Agentic Harness as Remediation Agent.
  • Runs in a dedicated, hardened gVisor sandbox container per job.
  • Needs customer-provided shared storage, restricted outbound networking, and the agentic container deployment.
  • Designed as scheduled analysis, normally daily on the main branch or per release.
SARA: Agentic Readiness Assessment
Available, Cloud only
  • SonarQube Cloud project and organization entitlement.
  • Available in the UI and through the MCP Agentic Readiness toolset.
  • Assessment reviews eight pillars and can take roughly 10 minutes.
  • Not available in the current Server agentic feature scope.
  • Do not position a Server equivalent as committed for 2026.5.

Support note: Server requirements above reflect current launch and architecture work, not final GA documentation. Validate exact editions, entitlement behavior, supported SCMs, LLMs, and sizing against the 2026.5 release docs once published.

Fast triage

The operational split

Cloud, check these first

  • Correct paid plan and Agent Essentials entitlement
  • Feature enabled at the organization
  • Recent CI scan and correct branch context
  • Personal token and project-scoped agent integration
  • Local CLI/MCP configuration, including an OCI runtime when MCP is used
  • For Remediation, source-control binding and an LLM API key

Server, check these first

  • 2026.5 LTA, correct edition, subscription, and accepted terms
  • Docker Compose or Helm deployment, not ZIP
  • Shared filesystem or S3-compatible storage provisioned
  • gVisor-based sandboxing and per-job containers
  • Egress policy permits only approved LLM and Sonar endpoints
  • LLM provider and SCM write/review permissions configured
Key support distinction: a Cloud failure is usually an entitlement, authentication, baseline-analysis, or local integration problem. A Server failure may also be caused by an incomplete infrastructure gate. Current Server setup work notes that missing activation, containers, LLM configuration, or SCM write access can result in work being accepted without a fix suggestion.
