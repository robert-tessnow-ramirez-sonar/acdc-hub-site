AC/DC · Guide + Verify

Onboard Sonar Vortex

Equip a coding agent with project-aware context before it writes code, then verify each change in real time inside the agent's own loop.

Cloud Team or Enterprise + Agent EssentialsContext augmentation and agentic analysis are separate Vortex capabilities enabled at the organization level.

What Vortex delivers

Vortex covers the Guide and Verify stages of the Agent Centric Development Cycle, inside the agent's own coding loop.

1

Context, before writing

Injects repository maps, architecture rules, security policies, and team conventions into the agent's prompt so it starts grounded.

2

Semantic code navigation

Lets the agent ask for a class, a method, or its callers directly instead of text-searching file by file, cutting exploration tokens.

3

Real-time verification

Reuses context from a prior CI analysis to run SonarQube's deterministic checks on each file in seconds, so the agent can self-correct before a PR.

Readiness checklist

Confirm these gates before installing Vortex in an agent.

Eligible planThe organization is on SonarQube Cloud Team (annual) or Enterprise, with a Sonar Agent Essentials subscription.
Long-lived branch analyzed in CIThe target project has completed a standard CI analysis on a long-lived branch, so Vortex can reuse that context for fast verification.
Organization adminAn administrator can enroll the organization and enable Vortex capabilities for target projects.
Supported agent or MCP clientClaude Code, Codex, Cursor, GitHub Copilot CLI, Antigravity, Kiro, or any agent that can connect to the SonarQube MCP server.

Install and run

Use this sequence for the first agent and project.

01Enable Vortex for the organization

Confirm the Cloud Team or Enterprise plan and the Agent Essentials subscription, then enable Vortex capabilities for the target organization.

02Install Vortex in the agent

Use the SonarQube CLI or plugin for a supported agent (Claude Code, Codex, Cursor, GitHub Copilot CLI, Antigravity, Kiro), or configure the SonarQube MCP server for any other agent.

03Check the setup

Confirm the agent can reach Vortex context and analysis tools before relying on it in a real task.

04Run a real task

Give the agent a normal coding task on the onboarded project and confirm it pulls context before writing and gets verification feedback as it edits files.

Supported agents

Vortex ships native install paths for these agents. Anything else can connect through the MCP server.

Claude CodeCodexCursorGitHub Copilot CLIAntigravityKiroSonarQube MCP Server
CI dependencyAgentic analysis reuses context collected during a CI analysis on a long-lived branch. If the target project or branch has never completed a CI scan, verification will not have the context it needs and should not be relied on yet.

How the loop works

Vortex sits inside the agent's own reasoning loop, not as a separate review step afterward.

1. GuideVortex injects repository context and constraints into the prompt before the agent drafts code.
→
2. WriteThe agent produces or edits code, informed by that context instead of guessing at conventions.
→
3. VerifyEach edited file is analyzed in seconds against SonarQube's deterministic rules.
→
4. Self-correctThe agent fixes flagged issues before the change ever reaches a PR or CI run.

Definition of a successful onboarding

Grounded

The agent visibly uses repository context and constraints instead of producing generic, environment-blind code.

Verified in-loop

Issues are caught and corrected inside the agent's own turns, measurably reducing rework at PR review and in CI.

Efficient

Token spend on blind file exploration drops, and fewer CI runs are needed to reach a passing quality gate.
