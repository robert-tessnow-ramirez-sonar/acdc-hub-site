How do you troubleshoot bad results from Remediation Agent?

QuestionCore

Goal: Build a troubleshooting checklist for when a fix doesn't show up, or looks wrong.

Where to look, not what to write
  • Read the "Scope limits" notice on this hub's Remediation Agent onboarding page as a starting list of hard limits, then check Remediation Agent for anything more specific about caps on PR size or excluded rules.
  • Ask yourself: what would make the agent simply not trigger at all (language, platform, issue count), versus what would make it trigger but discard its own fix (failed re-verification)? Those are two different failure modes worth distinguishing.
  • Also consider the LLM provider side: since the agent can run on a customer-supplied key, what happens if that key is missing, invalid, or the provider account has run out of credit?

Where is Remediation Agent hosted?

QuestionCore

Goal: Understand Remediation Agent's architecture, especially where the LLM call actually happens.

Where to look, not what to write
  • Read the "How a fix gets verified" flow on this hub's Remediation Agent onboarding page, then check Remediation Agent for how the LLM provider relationship actually works today.
  • Distinguish two things that are easy to conflate: where the orchestration/verification logic runs (Sonar's own service), versus which account the actual LLM inference is billed to and processed under. Who provides the API key, and what does that imply about whose usage agreement governs the code sent to the model?
  • Note that re-verification (re-running SonarQube's analysis engine against a candidate fix) is a distinct step from the LLM call itself, where does that verification step run?
