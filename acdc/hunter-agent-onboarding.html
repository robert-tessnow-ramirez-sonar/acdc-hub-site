Readiness checklist

Complete these gates before planning the first scan.

Enterprise planThe organization is on SonarQube Cloud Enterprise and eligible for the Hunter Agent beta.
DevOps bindingThe organization and target project are bound to GitHub, GitLab, or Azure DevOps.
Organization adminAn administrator can enroll the organization through Administration → AI capabilities.
Project adminA project administrator can enable scans, choose a branch, and set the scanning cadence.

Enable and run

Use this sequence for the first pilot project.

01Enroll the organization

Open the organization’s Administration → AI capabilities page, enroll in the Hunter Agent beta, and permit project admins to enable scheduled scans.

02Open the project’s Hunter Agent page

Go to Administration → AI capabilities → Hunter Agent. If organization enrollment or project binding is incomplete, resolve that gate first.

03Run a bounded first analysis

Select Run now and choose the intended branch. Monitor the Activity tab until the outcome is complete or failed.

04Set the operating cadence

After triaging the first run, use the daily schedule where appropriate, or align a controlled run with release and security-review milestones.

First-run guardrailDo not surprise a delivery team by running the first scan against a protected main branch without a triage plan. New findings can affect a currently passing quality gate. Start with a controlled branch or coordinate review capacity first.

How to work the results

Hunter Agent raises findings as regular SonarQube issues, so existing issue workflows remain the system of record.

1. Confirm run stateUse the Activity tab to confirm branch, start time, and outcome.
→
2. Filter findingsUse the hunter-agent tag or category tags to focus the review.
→
3. Validate signalFor each sampled issue, record credible, false positive, or needs investigation.
→
4. Assign ownershipRoute accepted issues through the team’s normal remediation and tracking workflow.

Hunter Agent complements static analysis. It analyzes source code in depth and does not run or attack a live application.

Definition of a successful onboarding

Operational

The project is enabled, the scan completes, and the activity history gives the team a clear operational record.

Reviewable

Findings are visible in the regular issue list and reviewers can assess a practical sample without a separate tool or handoff.

Valuable

The team identifies whether the agent surfaced credible logic-level risk or supplied trusted negative assurance for the pilot.
