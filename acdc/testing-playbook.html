Guide + Verify

Sonar Vortex

Primary developer workflow
01 · Integrate

Install the supported agent plugin and run its integration skill from the repository, or configure a local MCP server.

02 · Guide

Ask the agent to make a small, realistic change. Confirm it retrieves guidelines before edits and uses semantic navigation rather than broad text search.

03 · Verify

Have the agent modify one or more supported-language files, then run agentic analysis against the change set.

04 · Refine

Introduce an intentionally fixable quality or security issue. Confirm the finding is surfaced, fixed, and re-verified before the agent completes.

Pass evidence: agent output shows context retrieval, the analysis returns findings or a clean result, and the final change passes the relevant quality checks. Capture before/after diffs and the analysis response.
Solve

Remediation Agent

Backlog + PR
01 · Enable

Bind the project to GitHub or Azure DevOps, enable analysis, enable the agent, and configure the provider key. GitHub requires the SonarQube Agent app.

02 · Backlog

On a main-branch issue in a supported language, select Assign to Agent. Start with a simple maintainability or reliability finding.

03 · PR

For GitHub, open a PR containing a fixable issue that fails the quality gate, then allow the remediation workflow to run.

04 · Review

Review the generated PR and its Sonar result. Confirm scope is correct, the original issue is addressed, and no new issue is introduced.

Pass evidence: Agent activity has a completed session and a reviewable PR or suggestion. Verify the fix PR’s quality gate, then record whether the change is acceptable to a human reviewer. Do not auto-merge.
Verify · security

SonarQube Hunter Agent

Full-codebase analysis
01 · Select

Choose a GitHub-bound, main-branch project that has completed regular Sonar analysis and meaningful authentication, authorization, or business-logic code.

02 · Enable

Enable Hunter Agent for the project in AI capabilities, then start an on-demand run from the project settings or use the available scheduling option.

03 · Observe

Check the project’s Hunter Agent activity/history until the run is Completed or Failed. Avoid treating “no findings” as a failure.

04 · Validate

Review a small sample of findings with an AppSec or service owner. Compare signal quality to known risks or a manual test where possible.

Pass evidence: run status is Completed, and any findings appear in the project issue list. A completed run with zero findings is still a valid functional pass. Capture run state, duration, and reviewer disposition for sampled findings.
Readiness

SARA, Agentic Readiness Assessment

Cloud only · alpha
01 · Run

Open the project’s Agentic readiness page and select Run assessment. Alternatively use the entitled MCP toolset.

02 · Wait

Allow the asynchronous assessment to complete. Through MCP, poll the returned assessment ID rather than repeatedly starting new runs.

03 · Inspect

Record the overall level and review the eight pillar scores, evidence, gaps, and recommended actions.

04 · Re-test

Implement one bounded recommendation, for example documenting test commands or enabling Vortex, then run another assessment and compare the result.

Pass evidence: a completed report with an overall maturity level and per-pillar actions. The value test is whether the recommendations are specific enough to produce a measurable improvement in the next run.
Prompt library

Vortex · Guide + Verify

Change safely, then self-verify

Paste into connected agent
You are working in a SonarQube Cloud project with Sonar Vortex enabled. Before editing, retrieve the relevant Sonar coding guidelines and architecture or semantic-navigation context for this task. Make the smallest correct change to [DESCRIBE CHANGE]. Before you finish, run Sonar Vortex agentic analysis on every file you changed. If it reports new Critical, High, security, reliability, or maintainability findings on your edits, fix them and re-run the same analysis until clean. In your final response, list: 1) the context you used, 2) files changed, 3) each analysis run and outcome, and 4) any remaining non-blocking findings.
Remediation Agent · Solve

Create a controlled fix candidate

Evaluator brief
Use the SonarQube Cloud Remediation Agent to address issue [ISSUE KEY] in project [PROJECT]. Confirm the project is bound to its DevOps repository and that the agent is enabled. Trigger backlog remediation with Assign to Agent, or for GitHub, open a pull request that contains a known fixable issue and fails the quality gate. Do not merge any generated pull request. Record the Agent activity result, generated PR link, original issue status, fix PR quality-gate result, changed files, and a human review verdict: acceptable, needs changes, or reject.
Hunter Agent · Security

Run a bounded vulnerability hunt

Evaluator brief
In SonarQube Cloud, run SonarQube Hunter Agent for [PROJECT] on [MAIN BRANCH]. Confirm a regular Sonar analysis exists first. Select a project that contains authentication, authorization, session handling, payment, or other business-logic code. Start one on-demand run and monitor Hunter Agent activity/history until the state is Completed or Failed. A Completed run with zero findings is a valid functional result. For up to five findings, ask the application owner or AppSec reviewer to label each as credible, false positive, or needs investigation. Capture the run ID, status, duration, findings count, and evidence for each disposition.
SARA · Readiness

Measure and improve one readiness gap

UI or MCP
Run a Sonar Agentic Readiness Assessment for [PROJECT] in SonarQube Cloud. Use the Agentic readiness page, or the entitled MCP toolset if available. Wait for the assessment to complete, then record the overall readiness level and all eight pillar levels. Choose one recommendation that can be completed in this evaluation, such as documenting the exact test command, adding a reproducible local check, or configuring Vortex. Implement it in a controlled branch, then run SARA again. Report the before and after levels, the implemented recommendation, and whether the assessment gave an actionable improvement path.
5 · Decide

Evaluate outcomes, not just activation

Functional scorecard

  • Was the feature enabled and reachable by its intended user?
  • Did it complete without silent failure or an unclear state?
  • Was the expected output visible in the correct place, agent response, issue list, activity, or PR?
  • Could the test be repeated on a second project?

Value scorecard

  • Did Vortex reduce agent rework or catch an issue before CI?
  • Were Remediation Agent proposals safe and reviewable?
  • Did Hunter uncover a credible logic flaw or provide trusted negative assurance?
  • Did SARA give an actionable, owned next step?
Testing guardrail: use a non-production repository or a controlled branch. For Remediation Agent and Hunter findings, treat all generated output as a suggestion that requires human review. Do not merge agent-created PRs automatically.
