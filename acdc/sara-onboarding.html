AC/DC · Agentic readiness

Onboard SARA

Benchmark how ready a repository is for autonomous AI agents, across eight pillars, and get concrete actions to close the gaps.

SonarQube Cloud · AlphaCurrently limited to the SonarSource organization. Not yet generally available.

What SARA measures

SARA scores agentic friction, the unwritten knowledge and environmental hurdles that cause agents to underperform or act unsafely.

1

Benchmarks the environment

Evaluates the repository itself, not the model, across documentation, workflows, tooling, and safety guardrails an agent depends on.

2

Assigns a maturity level

Produces an overall L1 to L5 rating plus a per-pillar breakdown, so gaps are specific rather than vague.

3

Recommends fixes agents can run

Each gap comes with an actionable recommendation, machine-readable enough that an agent can pick it up and close it autonomously.

Readiness checklist

Confirm these gates before running the first assessment.

SonarSource organizationSARA is alpha and currently scoped to SonarSource-owned organizations only.
Feature flag enabledThe organization has agentic readiness assessment turned on so the project-level page and CLI calls are authorized.
Project bound and analyzedThe target project is bound to its repository on SonarQube Cloud, since SARA resolves and clones the default branch to assess it.
SonarQube CLI or MCP accessFor agent-triggered runs, the agent has SonarQube CLI or MCP server access to call the assessment API on demand.

Run the first assessment

Use this sequence for a project's first SARA report.

01Open Agentic readiness

In SonarQube Cloud, go to Your project → Agentic readiness in the left side menu.

02Run assessment

Select Run assessment. SARA clones the project's default branch and evaluates it against all eight pillars.

03Review the report

Check the overall readiness level, then open each pillar to see strengths, gaps, suggested actions, and findings grouped as Blocker, Negative, or Positive.

04Close gaps and re-run

Work through the recommended actions, starting with Blocker findings, then re-run the assessment to confirm the maturity level improved.

Runs against the default branchAn assessment evaluates the project's default branch on SonarQube Cloud, not local uncommitted changes. Merge or push changes you want reflected before running or re-running the assessment.

The eight-pillar model

Pillars map to the three AC/DC stages: Guide, Verify, and Solve.

Guide

Documentation and context

Can the agent build an accurate map of the codebase without asking a teammate for unwritten knowledge?

Guide

Workflow and contribution

Can work be proposed, verified, and integrated reliably, with explicit rules for branches, commits, and pull requests?

Guide

Dev environment

Can the agent go from clone to passing tests with zero manual intervention or unwritten local setup knowledge?

Verify

Build system

Can the agent produce a verifiable artifact fast and repeatedly, deterministically, across environments?

Verify

Testing

Can the agent know if a change works, with actionable feedback in a reproducible environment?

Verify

Code quality and style

Can the agent extrapolate patterns and write conformant code, with immediate automated feedback instead of waiting on CI?

Verify

Security

Can the agent operate safely within security and compliance boundaries, knowing the limits of its own autonomy?

Solve

Observability

Can the agent diagnose failures from structured, machine-readable runtime signals alone?

The five levels of maturity

Each pillar, and the overall project, is scored L1 through L5.

L1
Pre-agenticInitial tooling and guidance exist but lack cohesion, for example an incomplete README or undocumented setup tools.
L2
BasicQuality gates and documentation are in place; baseline standards are met but not optimized, such as reasonable test coverage and present CI checks.
L3
StandardizedAn agent-ready baseline lets an agent work autonomously with minimal guidance: documented conventions, an idempotent build, consistent vocabulary.
L4
Agent optimizedHigh-velocity agent workflows are enabled with tooling explicitly designed for agent navigation: automated quality gates, comprehensive observability, fast feedback loops.
L5
Agent nativeAutonomous workflows are fully operational; the codebase is self-describing, policies are machine-readable, and error recovery is automatic.

Definition of a successful onboarding

Baselined

The project has a first assessment on record, giving the team a concrete starting maturity level instead of a guess.

Actioned

Blocker findings are triaged first, and recommended actions are assigned or handed to an agent to close autonomously.

Trending up

Re-running the assessment shows the overall level, or specific pillar levels, improving over successive runs.
