What the agent delivers

Remediation Agent covers the Solve stage of the Agent Centric Development Cycle: it fixes what Verify already found.

1

Fixes PR quality gate failures

Monitors pull requests on SonarQube Cloud and generates a fix for issues that would otherwise fail the quality gate.

2

Clears the existing backlog

Works through reliability and maintainability issues, and SCA dependency vulnerabilities, found in your main branch analysis.

3

Re-verifies before it proposes

Every generated fix is re-scanned by Sonar's analysis engine. Only fixes that pass verification are offered as a pull request.

Install and run

Use this sequence to enable the first repository.

01Install the GitHub App

Install and connect the SonarQube Agent GitHub App to the organization. Permissions are scoped to read/write on code and pull requests, and read-only on issues and metadata.

02Enable PR fixes and backlog fixes

After installation, confirm both "Pull request fixes" and "Backlog fixes" show as enabled for the target repositories.

03Trigger a PR fix

On a pull request with a quality gate failure, check "Run Remediation Agent" in the sonarqube-agent bot comment to start fix generation.

04Delegate backlog issues

From the Issues page in SonarQube Cloud, use "Assign to Agent" on eligible backlog issues to have the agent open batch fix PRs.

Scope limitsPR fixes require GitHub today; GitLab and Bitbucket are not supported. Some rules per language are excluded as too complex for automated resolution and will surface under "Issues requiring manual fix" in the agent's comment instead of a generated fix.

Two ways to engage the agent

The agent addresses the "inner loop" (a single PR) and the "outer loop" (the whole backlog) differently.

Inner loop: pull requests

Triggered manually on a specific PR when a quality gate check fails. The agent proposes a fix scoped to that PR's new issues.

Outer loop: backlog

Triggered by assigning existing issues to the agent in SonarQube Cloud. The agent works through categories of technical debt autonomously and opens batch PRs for review.

How a fix gets verified

Nothing reaches your codebase without a re-scan and your sign-off.

1. DetectSonarQube analysis flags an issue in a PR or in the main branch backlog.
→
2. GenerateThe agent sends the affected code to an LLM to produce a candidate fix.
→
3. Re-scanSonar's analysis engine verifies the candidate fix does not introduce new issues.
→
4. Review and mergeOnly verified fixes become a pull request. You review and merge it like any other contribution.

Definition of a successful onboarding

Installed and scoped

The GitHub App is connected, and PR fixes and backlog fixes are enabled for the intended repositories.

Trusted

Reviewers can see that each proposed fix was re-scanned and verified before it reached them as a PR.

Reducing debt

The backlog issue count trends down over time as batch fix PRs get merged, without a manual triage bottleneck.
